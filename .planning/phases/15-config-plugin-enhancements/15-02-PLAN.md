## Goal

Extend the OpenAPI plugin to extract server connection hints from `servers[].url` (OAS3) and `host` (Swagger 2.0), and extend the Kubernetes plugin to extract connection info from `containers[].env` values. Both plugins use the shared `url_util.rs` created in Plan 15-01. These two plugins can be implemented fully in parallel — they share no data structures.

**Important:** This plan depends on `url_util.rs` existing (created in Plan 15-01). Since both plans are Wave 1, the executor of this plan must create `url_util.rs` themselves if Plan 15-01 has not run yet. In practice, run Plan 15-01 first; if running in strict parallel, duplicate the url_util.rs creation here with a `pub use` re-export.

**Practical instruction for executor:** Check if `src/plugin/config/url_util.rs` exists before starting. If it does not exist, create it as specified in Plan 15-01 Task 1 before proceeding with Tasks 2 and 3 here.

**Action:**

0. **FIRST: Split the combined match arm** — The current `extract()` method has a single `"Deployment" | "Service" => { ... }` match arm. Before adding any container env traversal, split it into two separate arms with identical ServiceInfo push logic:

```rust
// BEFORE (current code):
"Deployment" | "Service" => {
    if let Some(metadata) = manifest.metadata {
        if let Some(name) = metadata.name {
            result.services.push(ServiceInfo { ... });
        }

}

// AFTER (split into two arms):
"Deployment" => {
    if let Some(metadata) = manifest.metadata {

            // container env traversal added here in step 3
        }
    }
}
"Service" => {
    if let Some(metadata) = manifest.metadata {
        if let Some(name) = metadata.name {
            result.services.push(ServiceInfo { ... });
            // no container env traversal for Service kind
        }
    }
}
```

This split is required so that env traversal applies only to `Deployment` kind. `test_k8s_service_kind_no_env` verifies that `Service` kind does NOT emit env connections.

1. **Extend the `K8sManifest` struct chain** with the 4-level nesting for container env vars:

```rust
#[derive(Deserialize)]
struct K8sManifest {
    kind: Option<String>,
    metadata: Option<K8sMetadata>,
    spec: Option<K8sSpec>,          // ADD
}

#[derive(Deserialize)]
struct K8sSpec {
    template: Option<K8sTemplate>,
}

#[derive(Deserialize)]
struct K8sTemplate {
    spec: Option<K8sPodSpec>,
}

}

    #[serde(default)]
    env: Vec<K8sEnvVar>,
```

2. **Add imports:**

3. **Update the `extract()` method** — in the `"Deployment"` arm, after emitting `ServiceInfo`, add container env traversal. Use `if let Some(...)` chains to safely traverse the nested optional spec fields:

```rust
"Deployment" => {
    if let Some(metadata) = manifest.metadata {
        if let Some(name) = metadata.name {
            // ... existing ServiceInfo push ...

            // ADD: Extract connections from containers[].env
            if let Some(spec) = manifest.spec {
                if let Some(template) = spec.template {
                    if let Some(pod_spec) = template.spec {
                        for container in pod_spec.containers {
                            for env_var in container.env {
                                if let Some(val) = env_var.value {
                                    if is_connection_key(&env_var.name) {
                                        if let Some((protocol, hostname)) = parse_url_value(&val) {
                                            result.connections.push(ConnectionInfo {
                                                source_service: name.clone(),
                                                target_name: hostname,
                                                protocol,
                                                method: None,
                                                path: None,
                                                source_file: format!("{}:0", file.relative_path),
                                                confidence: Confidence::High,
                                                extraction_method: "kubernetes".to_string(),
                                                dependency: None,
                                                evidence: Some(format!("{}={}", env_var.name, val)),
                                            });
                                        }
                                    }
                                }
                            }
                        }
                    }
                }
            }
        }
    }
}
```

The `name` variable is used both for `ServiceInfo` and as `source_service` in connections — use `.clone()` when needed.

## Threat Model

| Boundary | Description |
|----------|-------------|
| OpenAPI YAML/JSON → ConnectionInfo | Untrusted spec file content parsed for server URLs |
| Kubernetes YAML → ConnectionInfo | Untrusted manifest container env values parsed for URLs |

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-15-04 | Information Disclosure | openapi.rs parse_openapi_3 servers | accept | Server URLs in OpenAPI specs are public API documentation; extracted hostnames go into scan payload only, not executed |
| T-15-05 | Denial of Service | kubernetes.rs container env loop | accept | Containers slice is bounded by manifest file size; scanner already limits file size; O(containers × env_vars) is small in practice |
| T-15-06 | Tampering | kubernetes.rs valueFrom entries | accept | valueFrom with no `value` field produces None → silently skipped; no incorrect target emitted |
| T-15-07 | Spoofing | Swagger 2.0 host field | accept | host is string-parsed only; prepending http:// for Url::parse is safe — the scheme is discarded after hostname extraction |
