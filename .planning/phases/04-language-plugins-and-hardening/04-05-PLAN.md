  <behavior>
    Framework marker check (LPLU-08):
    - Scan ctx.files for "pom.xml" and "build.gradle"
    - pom.xml: content.contains("spring-boot-starter-web") OR content.contains("spring-boot-starter")
    - build.gradle: content.contains("spring-boot-starter-web")
    - If no marker: skip route detection, proceed to client detection only

    Two-phase Spring extraction (DETQ-05):

    Phase A — build class→prefix map per file:
    Query:
    ```scheme
    (class_declaration
      (modifiers
        (annotation
          name: (identifier) @ann_name
          arguments: (annotation_argument_list
            (string_literal) @prefix)?))
      name: (identifier) @class_name)
    ```
    Filter: @ann_name in ["RestController","Controller","RequestMapping"]
    If no annotation argument → prefix = "" (just marks the class as a controller)
    Build: HashMap<class_name, prefix_path>

    Note: Java @RequestMapping can have positional string OR named value= / path= pairs:
    `@RequestMapping("/path")` vs `@RequestMapping(value="/path")` vs `@RequestMapping(path="/path")`
    Use element_value_pair to also capture named arguments:
    ```scheme
    (annotation_argument_list
      [(string_literal) @prefix
       (element_value_pair
         key: (identifier) @kv_key
         value: (string_literal) @prefix)])
    ```
    Accept prefix from either positional or from pair where @kv_key in ["value","path"]

    Phase B — method-level route annotation:
    Query:
    ```scheme
    (method_declaration
      (modifiers
        (annotation
          name: (identifier) @method_ann
          arguments: (annotation_argument_list
            [(string_literal) @path
             (element_value_pair
               key: (identifier) @pk
               value: (string_literal) @path)])?))
      name: (identifier) @method_name)
    ```
    Filter: @method_ann in ["GetMapping","PostMapping","PutMapping","DeleteMapping","PatchMapping","RequestMapping"]
    Infer HTTP method from annotation name: GetMapping→GET, PostMapping→POST, etc.
    For @RequestMapping: check for additional method= element_value_pair to extract method; default GET

    Join: walk method_declaration's parent chain to find enclosing class_declaration name,
    look up in Phase A class map, prepend prefix. Full path = prefix + (method_path or "").

    Tests:
    - `@RestController @RequestMapping("/api/v1") class OrdersController { @GetMapping("/orders") public void list() {} }`
      → EndpointInfo GET /api/v1/orders
    - `@RestController class UserController { @GetMapping("/users") public void list() {} }`
      → EndpointInfo GET /users (no class-level prefix)
    - No Spring marker in pom.xml → no routes detected
  </behavior>
  <action>
    Implement java.rs.

    The two-phase join must work within a single file parse. Strategy:
    1. Parse file once with tree_sitter_java::language()
    2. Traverse AST: collect class_declaration nodes with controller annotations → build prefix_map HashMap<&str, &str>
    3. Traverse AST: collect method_declaration nodes with mapping annotations
    4. For each method node, call node.parent() repeatedly to find containing class_declaration
    5. Look up that class's name in prefix_map
    6. Build full path = prefix + method_path

    Note on tree-sitter node traversal for class membership:
    `method_declaration` is typically a direct child of a `class_body`, which is a child of `class_declaration`.
    Walk: method_declaration.parent() → class_body, class_body.parent() → class_declaration.

    Java string literals use `string_literal` node type (not "string"). Include quotes in capture,
    then strip: text.trim_matches('"')

    Use OnceLock for all query constants. file_patterns: ["**/*.java","**/pom.xml","**/build.gradle"]
  </action>
